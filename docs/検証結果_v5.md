## 2. 実装したもの（設計書v4追記のとおり）

### 2.1 記録時（`-Record`）

`wait_after` の質問の**直後に**、続けて次を聞くようにした。表示は `wait_after` とまったく同じ書式（`Get-ActionDesc` を共有）。

```
対象者ごとに表示が変わる操作はどれですか？（全 12 手順）
  1: goto http://localhost:8765/index.html
  2: click #link-shomei-roster (証明書発行（氏名だけの一覧）)
  3: expect_url http://localhost:8765/roster.html
  4: fill #input-atena = {{atena}}
  5: click #btn-search (検索)
  6: click tr.p-selectable-row (山田 太郎)
  7: setcheck 世帯主 = False
  8: setcheck 続柄 = False
  9: setcheck 本籍 = True
 10: setcheck 個人番号 = False
 11: click #btn-issue (発行)
 12: click #btn-confirm-yes (はい)
番号をカンマ区切りで入力（Enterで設定しない）: 6
```

- 複数可（カンマ区切り）／Enterのみなら設定しない
- 不正な番号（数字以外・範囲外）は警告を出して**その番号だけ無視**
- **`click` 以外が選ばれたら警告を出して無視**
- 選ばれた手順は `"by_index": true` を付け、**`text` を保存せず**、`"index": <記録時の並び順(1始まり)>` を付ける

`index` は記録時にブラウザ側で採っている。クリックした瞬間に
「そのとき決まったセレクタで `document.querySelectorAll()` した結果の中で自分が何番目か」を数え、
記録イベントに載せている（記録の質問はEdgeとの接続を閉じた後に出るので、後から数え直すことはできないため）。

### 2.2 再生時

`by_index: true` の click は、ボタン名の照合を**一切行わない**。

1. セレクタで取れる要素のうち、**画面に見えているもの**を数える
2. **ちょうど1件** → それを押す（押し方は既存の `go()`＝`click()` があればそれ、無ければ作ったマウス操作）
3. **0件** → `action_timeout_ms` まで待ってから失敗（`位置で押す対象が見つかりません: …`）
4. **2件以上** → **押さずに失敗**（`位置で押す対象が2件見つかりました(1件のはず): …`）

`index` は再生で対象を選ぶのには**使っていない**（設計書のとおり。複数件から `index` 番目を選ぶ動作は作っていない）。
§8.2 で `index` を 3 に書き換えても、見えているものが1件ならその1件を押すことを実測した。

押し方（`visible` / `rawClick` / `go`）は通常のクリックと同じものを使うため、
JSを `$script:ClickHelpersJs` に切り出して両方から埋め込むようにした（コピーを増やして食い違うのを避けるため）。

## 3. 練習ページに足したもの（`test/mock/roster.html`）

実環境と同じ条件にした：

- 対象者一覧の行は **`<tr class="p-selectable-row" tabindex="0">`**（PrimeVue系）
- **行の表示は氏名だけ**（宛名番号を出さない）
- **行に宛名番号を含む属性を持たせない**（宛名番号はクリックのハンドラが閉じ込めて持つだけ）
- **選択後の印字画面にも宛名番号を出さない**（`対象者: 山田 太郎` のみ）

記録中にページから読み出した実際の行（実測）:
```
一覧の行数: 1 / 行の表示: 山田 太郎
行の属性: <tr class="p-selectable-row" tabindex="0"><td>山田 太郎</td></tr>
```

帳票の代用である「発行済みリスト」には、**誰の帳票が出たかを確かめるため宛名番号と氏名を残している**
（画面には出ないが出力物には載っている、という実環境と同じ関係）。

検証用スイッチ `（検証用）氏名だけの一覧の検索結果を複数件にする`（メニュー画面）をONにすると、
検索がDBの全員を返し、一覧が**3件**になる。G19で使う。

## 11. 設計書から離れた点・こちらの判断で埋めた点

1. **`index` をブラウザ側（記録JS）で採った。**
   設計書は「記録時にそのセレクタで取れたものの中で何番目か」としか書いていない。
   記録の質問はEdgeとの接続を閉じた後に出るため、後から数え直すことはできない。
   そこでクリックした瞬間に数えて記録イベントに載せ、選ばれた手順にだけ `index` として残し、
   選ばれなかった手順の分は保存前に捨てている（記録ファイルに余分な項目を増やさないため）。
2. **「2件以上」は待たずにその場で失敗にした。**
   設計書は0件のときだけ「`action_timeout_ms` まで待ってから」と書いており、2件以上には待ちの指定が無い。
   描画の途中で件数が減ることは無いので、待っても結果は変わらないと判断した。
3. **新しい画面を `app.html` に足さず、別ページ（`roster.html`）にした。**
   既存ページの一覧表示を変えると G2・G6・G9 が測れなくなるため。設計書も「別ページか切替で」としている。
4. **一覧を複数件にする方法は、メニュー画面の検証用スイッチにした。**
   設計書は「2件以上表示される状態を作る」としか書いていないので、作り方はこちらで決めた
   （`app.html` の「印字項目の初期状態を反転する」スイッチと同じ作りに揃えた）。
5. **一覧の列は氏名1列だけにした。** 設計書の例（`click tr.p-selectable-row (山田 太郎)`）に合わせた。
   実環境は列がもっと多い可能性がある（§12-3）。
6. **同じ番号を2回書いた場合は1回だけ採用、複数指定は番号の小さい順に印を付ける。**
   `wait_after`（v3）と同じ扱いに揃えた。設計書に記載が無いので決めた。
7. **空のカンマ（`6,,9`）は警告なしで読み飛ばす。** これも `wait_after` と同じ扱い。
8. **クリックの押し方JS（`visible` / `rawClick` / `go`）を `$script:ClickHelpersJs` に切り出した。**
   設計書の「押す方法は既存の `go()` をそのまま使う」を、コピーではなく共有で実現するため。
   既存のクリックの動きは変えていない（G2・G9・G14・G15 で再確認済み）。
9. **記録の確認表示で、消したボタン名を1行出すことにした**（`ボタン名「山田 太郎」は保存しません`）。
   設計書に指定は無いが、「氏名が保存されない」ことは人が確かめたい情報だと判断した。

## 12. 未実測・未解決・気になっている点

1. **`by_index` と `-DryRun` の組み合わせは未実測。**
   位置で押すクリックが `final`（出力実行ボタン）になる形は作っていない。
   実装上は `final` の手前で打ち切るので影響しないはずだが、**測っていない**。
2. **`by_index` を2手順以上に付けた再生は未実測。**
   記録時に複数指定できることは G20 の入力で通っている（正しい番号は1つだけ採用された）が、
   **2つ以上が採用された記録を作って流してはいない**。実装は手順ごとに独立して動くので同じはず。
3. **一覧の列が複数あるとき（実環境）の挙動は未実測。**
   練習ページの行は氏名1列。実環境の行が何列かは分かっていない。
   `by_index` はボタン名を見ないので、列が増えても押す動作は変わらないと考えているが、
   影響が出るとすれば**記録時のセレクタの決まり方**（行ではなく中の `<td>` が対象になる等）。
   **本物で1回録って、行を選ぶ手順のセレクタが行（`tr…`）になっているか目視してほしい。**
4. **セレクタが行以外（`td` や中の要素）になった場合の見え方は未確認。**
   その場合でも「見えているものがちょうど1件」で守られるが、1件に絞れず毎回失敗する可能性がある。
   そのときは `index` ではなくセレクタの見直しが必要（記録ファイルを手で直す）。
5. **`visible()` の判定は `offsetParent` と `getClientRects()` を見ている。**
   画面外にスクロールアウトしているだけの行も「見えている」と数える。
   一覧が長くて行が画面外にある実環境では、件数の数え方がこちらの想定とずれる可能性がある（練習ページでは1件なので出ない）。
6. **v3・v4 の未解決点はそのまま**（役割属性の無いただのsvgは記録されない／`wait_after_ms` は帳票ごとに変えられない／
   くるくるが `wait_after_ms` より長いと同じ症状に戻る、など）。今回の変更では触れていない。
7. **G1・G3・G4・G5・G8・G10〜G13・G16 は再実測していない**（指示された範囲がG17〜G20とG2・G6・G9・G7・G14・G15のため）。
   ただし G1 相当（`{{atena}}` 置換の箇所数）と G16 相当（不正な番号の無視）は今回の記録の中で観測している。
8. **GUIランチャーは未実測**（v2から変わらず）。今回の変更はランチャーに手を入れていない。
9. **READMEの第5部「困ったとき」には今回の症状の項目を足していない。**
   設計書が指定した更新箇所（第2部 手順2／第4部のアクション一覧／元に戻す方法）だけに絞ったため。
   「2人目以降だけ失敗する」の見出しで案内を足すのは有効だと思うので、必要なら指示がほしい。
