### v2 で練習ページに足したもの

**発行ボタンの後に確認ダイアログ（はい／いいえ）** を追加した（G12用。`app.html` と `spa.html` の両方）。

- 「発行」を押すと `#confirm-dialog` が表示されるだけで、帳票は出ない
- 「はい」（`#btn-confirm-yes`）を押して初めて発行済みリストに積まれる
- 「いいえ」（`#btn-confirm-no`）でダイアログを閉じる

つまり **v2 の練習ページでは「最後のクリック」＝「はい」であり、「出力実行ボタン」＝その1つ前の「発行」** という、
v1では表現できなかった構図になっている。

### 記録（-Record）の自動化

v1と同じ方式（本物のコンソールを持つ別プロセスで記録を起動し、ブラウザ操作はCDPの2つ目のクライアントから流し、
終了のEnterは `AttachConsole` + `WriteConsoleInput` でそのプロセスのコンソール入力バッファへ直接書き込む）。
v2では**出力実行ボタンの番号選択**が増えたので、同じ経路で `4` + Enter を送っている。

## 6. v2 での変更点（実装側）

| 設計書 v2 | 実装 |
|---|---|
| A. クリックを消さない | `Add-RecordSample` のURL変化処理を変更。保留クリックがあれば **クリックを確定してから `expect_url` を足す**。保留クリックが無いURL変化だけ `goto` にする |
| A. expect_url の再生 | `Invoke-CapAction` に `expect_url` を追加。オリジン＋パス＋ハッシュで一致するまで `load_timeout_ms` 待ち、一致しなければ例外（＝その件を失敗）。一致後は `Wait-PageReady` |
| A. クリック0件なら保存中止 | `Start-JobRecording` でクリック数を数え、0なら警告して `return`（保存しない） |
| A. gotoのURLも置換対象 | `Convert-AtenaPlaceholder` と `Expand-JobAction` を `url` にも適用（`goto`・`expect_url` の両方） |
| B. DryRunは `dry` | `Invoke-PrintRun` の status を `if ($DryRunMode) { "dry" } else { "ok" }` に。スキップ判定は `ok` のみ（v1から変更なし）。連続失敗の判定は `-ne "fail"` に修正 |
| C. 出力ボタンを番号で選ぶ | 最後の5クリックを番号付きで表示し `Read-Host`。Enterのみなら最後のクリック。範囲外・数字以外なら警告して最後のクリック |
| C. final以降はDryRunで飛ばす | `Invoke-JobForAtena` で final に当たったら `break`。証跡 `after` は**手順を最後まで流し終えた後**に撮る（DryRunでは撮らない） |

変更したファイル: `powershell/cdp_print.ps1` / `README.md` / `test/mock/app.html` / `test/mock/spa.html` / `docs/検証結果_v2.md`（新規）。
**v1の他の動作（アクション種別・待機・台帳の形式・GUI・start_edge）は変えていない。**

## 7. 設計書から逸脱した点・解釈で埋めた点（v2分）

1. **`expect_url` の一致後に `Wait-PageReady` を入れた（解釈）**
   設計書は「一致するまで待つ」までしか書いていないが、通常遷移（本物のページ移動）では
   URLが変わった直後はまだ描画中のことがある。v1の `goto` が `Page.navigate` のあとに `Wait-PageReady` していたのと同じ扱いに揃えた。
2. **`expect_url` の照合は「オリジン＋パス＋ハッシュ」の一致で実装（解釈）**
   設計書は「完全一致を基本とし、クエリは無視に緩める」。両方を段階的に試す作りにはせず、
   **常にクエリを無視した比較**にした（緩いほうだけを実装）。ホスト名の違いは検出できる。
3. **`expect_url` のURLも `{{atena}}` 置換の対象にした（解釈）**
   設計書Aの最後は「`goto` のURLも」だが、`expect_url` の再生は「`{{atena}}` 置換後の完全一致」と書かれているため、
   `expect_url` にも置換が要ると判断した。実装は「`url` を持つアクションすべて」に適用している。
4. **番号選択の入力が不正なとき（数字以外・範囲外）は、警告を出して最後のクリックを採用（解釈）**
   設計書に指定がないため。黙って採用せず必ず警告を出す。
5. **v1からの継続分**（`-Evidence` パラメータの追加、`setcheck` の `label` フォールバック、手順ファイルの `target_url_keyword` 優先、
   `.gitkeep` を置かない、`fill` の置換は完全一致のみ）は v1 検証結果 §4 のまま。

## 8. 未解決・気になっている点

1. **SPAでは記録の基準画面がアプリの中でなければならない。** `spa_mode=true` の `goto` は pushState しかしないため、
   アプリ外のページから録ると再生時にそのページを開けない。**仕様ではなく運用ルールとしてREADMEに書いた**だけなので、
   録り方を間違えると気づきにくい（記録開始時に「このタブはアプリ内か」を判定する手段が無い）。
2. **`expect_url` はパスが実行のたびに変わる作り（`/detail/98765` のような画面）には対応できない。**
   宛名番号が乗るケースは `{{atena}}` 置換で拾えるが、システムが振る内部IDがURLに乗ると毎回不一致になる。
   その場合は手順ファイルから該当の `expect_url` 行を手で消すしかない（消せば v1 と同じ挙動に戻る）。
3. **確認ダイアログの「いいえ」側は未実測。** G12は「はい」を押す経路だけを流している。
4. **`final` より前に確認ダイアログが出る画面**（出力ボタンの前に「よろしいですか」が出るタイプ）は未検証。
   その場合 `final` に選ぶべきは確認の「はい」のほうになるが、番号選択で選べるので仕様上は対応できているはず（未実測）。
5. **v1から持ち越しの未実測**: `select` / `wait` / `keyboard` アクション、GUIランチャーの画面操作、`ready_selector` の待機、
   `max_consecutive_fail`（v1で実測済み・v2では再実測していない）。
6. **練習ページと本物の差**（自動生成IDでセレクタが位置指定になる弱さ）は v1 のまま。
