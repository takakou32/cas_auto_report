# cas_auto_report 設計書（兼 実装発注書）v1

2026-08-27 起草。発注者：お姉さん（統括）／実装：ワーカー（Opus 5）／最終検分：Tくん（実機）

## 1. 目的

業務システム（住民記録・印鑑登録）をブラウザ越しに自動操作し、対象者（宛名番号）ごとの帳票出力操作を繰り返すツール。
帳票の実体はサーバ側の出力管理に溜まる。**回収は別ツールで行うため本ツールの対象外。**

[cas_cap](https://github.com/takakou32/cas_cap)（ローカル: `/mnt/c/work/cas_cap`）の姉妹ツール。
**構成・操作感・コードの流儀（コメントの書き方・関数分割・命名・メッセージの言い回し）をcas_capに揃えること。**

## 2. 前提環境

- Windows 10/11、PowerShell 5.1以上、**追加インストール不要（外部依存ゼロ）**
- Microsoft Edge（デバッグポート付き起動）
- 認証exeがEdgeのタブとして業務システムを開く構成
- 対象システムはWebアプリ。SPA（リロードなし遷移）の可能性あり

## 4. 動作モード

### 4.1 タブ一覧: `-List`

cas_capと同じ。接続中Edgeのタブ一覧を表示して終了。

### 4.2 記録: `-Record`

```powershell
.\powershell\cdp_print.ps1 -Record -Job R001_住民票 -Atena 1234567890 [-Config config/config.json]
```

- cas_capの `Start-Recording` 一式を土台にする
- 使う人は、メニューの基準画面から出力完了まで一通り手で操作し、Enterで記録終了
- 保存先: `jobs/<Job>.json`
- **記録後の自動処理（本ツールの肝）**:
  1. `fill` の value が `-Atena` の値と一致 → `{{atena}}` に置換
  2. `click` の text / selector に `-Atena` の値が含まれる → **その部分文字列を** `{{atena}}` に置換
     （検索結果の行クリックで「1234567890 山田 太郎」のようにボタン名へ番号が写り込むケースの対策）
  3. チェックボックス／ラジオへのクリックは `click` ではなく **`setcheck`** として記録する。
     クリック後の checked 状態を読み取り、`checked: true/false`（＝最終的にどの状態であるべきか）を保存
  4. 置換が1箇所もなければ警告を出す（宛名番号を入力しない帳票は想定外）
- 記録終了時、**最後のクリックを「出力実行」ボタンとみなし、確認プロンプトを出したうえで** そのアクションに `"final": true` を付与する（DryRunで使う）

### 4.3 実行（再生）

```powershell
.\powershell\cdp_print.ps1 [-Job R001_住民票] [-DryRun] [-Limit N] [-Config ...]
```

- `-Job` 省略時: `jobs/` 内の全帳票を名前順に処理
- 各帳票について `targets/<Job>.csv` を読み、1行（1宛名番号）ずつ:
  1. ledger に成功記録がある組（job×atena の最新行が ok）は**スキップ**（＝中断→再実行で続きから）
  2. 手順を頭から再生。`{{atena}}` を当該番号に差し込む（fill値・クリック照合テキストの両方）
  3. `setcheck` は要素の現在の checked を読み、**指定と違うときだけクリック**する
  4. 成功/失敗を ledger.csv に追記
  5. 件間ウェイト（config: `interval_ms`、既定 1000）
- `-DryRun`: `final: true` のアクションを実行しない（＝出力ボタンを押さない）。それ以外は全部流す
- `-Limit N`: 全体で N 件処理したら終了
- 証跡スクショ（config: `evidence` = `none` | `before` | `after` | `both`、既定 none）:
  final アクションの直前/直後に表示領域のスクショを `output/<Job>/<atena>_before.png` 等で保存。
  cas_capの `Save-Screenshot` を流用（モーダル/iframe展開などの全画面対応は不要。表示領域のみで簡略化してよい）

### 4.4 失敗の扱い（cas_capからの重要な変更）

- cas_capは「対象が見つからなければ警告してスキップし続行」だが、本ツールでは
  **「対象が見つからない・waitタイムアウト・例外 → その件を即失敗として打ち切り、次の宛名番号へ」**。
  理由: ズレた画面のまま進んで**誤った対象で出力ボタンを押す事故**を防ぐため
- 失敗しても実行全体は止めない。ただし**連続失敗が閾値（config: `max_consecutive_fail`、既定 5）に達したらその帳票を中断**して次の帳票へ（システム側の異常や手順の陳腐化の可能性が高いため）
- 各件の再生は必ず手順の先頭（基準画面への遷移操作）から始まるので、前の件の失敗で画面がどこにいても立て直せる前提。
  **README に「記録は必ずメニューの基準画面から録り始める」ルールを明記すること**

### 4.5 ledger.csv 形式

```csv
job,atena,timestamp,status,error
R001_住民票,1234567890,2026-08-27 19:00:00,ok,
R001_住民票,1234567891,2026-08-27 19:00:12,fail,クリック対象が見つかりません: ...
```

- **追記のみ**（上書きしない）。再実行時は job×atena の最新行で判定（ok→スキップ、fail→再試行）
- UTF-8 BOM付きで書く（Excelでそのまま開けること）

### 4.6 targets CSV 形式

- 1列目が宛名番号。ヘッダ行あり（`atena`）
- 2列目以降は無視する（氏名などのメモを書いてよい）

### 4.7 jobs JSON 形式

cas_capの recorded.json を踏襲しつつ、撮影ポイントごとの pages 分割は廃止（撮影しないため）。1本の actions 配列にする。

```json
{
  "job": "R001_住民票",
  "target_url_keyword": "…",
  "spa_mode": true,
  "actions": [
    { "type": "goto",  "url": "…" },
    { "type": "fill",  "selector": "…", "value": "{{atena}}" },
    { "type": "click", "selector": "…", "text": "{{atena}} 山田 太郎" },
    { "type": "setcheck", "selector": "…", "label": "氏名", "checked": true },
    { "type": "click", "selector": "…", "text": "発行", "final": true }
  ]
}
```

- goto/URL変化の検出・SPA判定（spa_mode）は cas_cap の記録ロジックをそのまま流用
- click の再生照合で `{{atena}}` を含む text は、差し込み後の**宛名番号のみで部分一致**させる（氏名部分は照合に使わない）

### 4.8 config.sample.json

```json
{
  "cdp_url": "http://localhost:9222",
  "target_url_keyword": "your-app-url",
  "settle_ms": 800,
  "stable_ms": 1000,
  "load_timeout_ms": 30000,
  "action_timeout_ms": 5000,
  "ready_selector": "",
  "spa_mode": false,
  "interval_ms": 1000,
  "max_consecutive_fail": 5,
  "evidence": "none",
  "viewport": { "width": 1280, "height": 800, "device_scale_factor": 1 }
}
```

共通項目は cas_cap と同じ名前・同じ意味を保つこと。

cas_capの `gui/launcher.ps1` と同じ見た目・同じ起動方式（launcher.bat、新しいコンソールで実行、EncodedCommand二重方式の `Start-InConsole` を流用）。

# v2 追記（2026-08-27・二周目の発注）

v1の検証（docs/検証結果_v1.md）で見つかった3点を直す。**v1の他の動作は変えない。**

## A. クリックを消さない（SPA対応）— 最優先

### 問題
v1の記録（cas_cap流用）は「クリック直後にURLが変わったら、そのクリックを捨てて宛先URLへの `goto` に置き換える」。
SPA（pushState遷移）では検索・対象者選択・発行のクリックが全部消え、再生すると台帳にokと書かれるのに帳票が出ない。

### 直し方
- **クリックは必ず `click` として残す。** URL変化を理由にクリックを捨てる処理を廃止する
- クリック直後のURL変化は、`goto`（移動）ではなく **`expect_url`（このURLになったことを確認する）** という新しいアクションとして、そのクリックの直後に記録する
  ```json
  { "type": "click", "selector": "#btn-search", "text": "検索" },
  { "type": "expect_url", "url": "http://…/spa.html#/result" }
  ```
- `expect_url` の再生：現在のURLが記録のURLと一致するまで待つ（上限 `load_timeout_ms`）。一致しなければその件を失敗にする。
  一致の判定は **`{{atena}}` 置換後の完全一致** を基本とし、クエリ文字列に差が出やすいので **パスとハッシュまでの一致（クエリは無視）** に緩める
- `goto` として記録するのは **直前にクリックが無いURL変化だけ**（記録開始時の初期URL、アドレスバー直打ち等）
- 記録開始時の現在URLは、手順の先頭に `goto` として入れる（v1と同じ）。**ただしSPAの場合、記録はアプリ内の基準画面から始めるルールをREADMEに明記**（v1検証§3で判明した「spa_modeだとgotoがpushStateしかしない」問題への運用上の対処）
- **クリックが1つも記録されなかった場合は保存しない**（警告ではなく中止）
- `goto` のURLも `{{atena}}` 置換の対象に加える（検索がGETでURLに宛名番号が乗る作りへの備え。v1検証§4-6）

## B. DryRunは台帳に `dry` と書く

- DryRun実行時、台帳の status は `ok` ではなく **`dry`** にする
- 本番実行のスキップ判定は **`ok` のみ**（`dry` は処理済み扱いにしない）
- README の注意書き（「DryRun後は台帳を消せ」系）は削除し、この仕様に書き換える

## C. 出力ボタンを記録終了時に選ばせる

- v1は「最後のクリック＝出力ボタン」の決め打ち。出力ボタンの後に確認ダイアログの「はい」がある画面だと、DryRunでも帳票が出てしまう
- 記録終了時、**最後の5回分のクリックを番号付きで表示し、どれが出力ボタンかを番号で選ばせる**（Enterだけなら最後のクリック＝v1と同じ）
- 選んだクリックに `final: true` を付ける。それ**以降のアクションは DryRun では実行しない**（final以降を全部飛ばす）
- 証跡 `before` は final の直前、`after` は手順の最後まで流し終えた後に撮る

## 検証（v2）

練習ページの通常遷移版・SPA版の両方で、G1〜G6を再実測する。加えて:

| # | 条件 |

# v3 追記（2026-08-28）：操作後の待ち（wait_after）

## 背景（実環境で判明）

住民記録システムの帳票画面は、**画面に着くと自動で印刷プレビューを作り始める**（既定のチェック状態で）。
その作成中は「くるくる」が出ており、この間にツールがプレビューボタンを押すと**押下が無効になる**。

すり抜けた理由：ツールの「画面が落ち着くまで待つ」仕組みは画面の中身の変化を見ているが、
**くるくるは絵が回っているだけで中身が変わらない**ため、静かになったと判断されてしまう。

くるくるの目印を機械が探す案・設定に登録する案も検討したが、**Tくん裁定で「待つ場所を記録時に人が指名する」方式**を採る。
判定は行わず、決めた秒数だけ待つ。

## 仕様

### 記録時（`-Record`）

出力実行ボタンの選択（既存）の**直後に**、続けて次を聞く。

```
実行後に待たせる操作はどれですか？（全 12 手順）
  1: goto http://.../menu
  2: click 証明書発行
  ...
 11: click プレビュー
 12: click 発行
番号をカンマ区切りで入力（Enterで設定しない）: 8,11
```

- **全手順が対象**（click に限らず goto / fill / setcheck / expect_url も選べる）
- **複数可**（カンマ区切り。空白が混じってもよい）
- Enterのみなら設定しない
- 番号が不正（数字以外・範囲外）なら警告を出し、**その番号だけ無視**して残りを採用する（黙って採用しない）
- 選ばれた手順に `"wait_after": true` を付けて保存する

一覧の表示形式は、記録終了時にすでに出している手順一覧と**同じ番号・同じ書式**にすること（人が突き合わせられるように）。

### 再生時

`wait_after: true` の手順は、**その手順を実行した後に `wait_after_ms` だけ待つ**。

- 待ち時間は `config.json` の `wait_after_ms`（既定 **5000**）。記録ファイルには秒数を持たせない（録り直さずに調整できるようにするため）
- `-DryRun` でも同じように待つ（`final` 以降は実行しないので、そこに付いた印は自然に効かない）
- 待ちは `Start-Sleep` でよい（画面の状態は見ない。これは意図した割り切り）

### config.json

| キー | 既定 | 説明 |
|---|---|---|
| `wait_after_ms` | 5000 | `wait_after` が付いた手順の後に待つ時間(ms) |

`config.sample.json` にも追加すること。

### README

第2部 手順2（記録）に、この質問と答え方を追記する。
第4部の設定項目の表・アクション一覧（`wait_after` の説明）にも反映する。

## 検証（G14〜G16）

# v4 追記（2026-08-28）：位置で押す（by_index）

## 背景（実環境で判明）

対象者一覧から対象者を選ぶクリックが、**記録した1人目でしか成功しない**。

原因：記録時、クリックの照合用に「ボタン名」（`text`）を保存している。
一覧の行に**宛名番号が表示されず氏名だけ**の場合、`{{atena}}` への差し替えが起きず
「山田 太郎」がそのまま残る。再生時、2人目以降は行の表示が「佐藤 花子」なので照合が外れ、
`クリック対象が見つかりません` で失敗する。

実環境の行は `<tr class="p-selectable-row">`（PrimeVue系）で、**宛名番号を含む属性は無い**。
選択後の画面にも宛名番号は表示されない。

対策として、宛名番号で検索した結果は必ず1件になることを利用し、**位置で押す**方式を採る。
ただし過去に位置指定で失敗した経験があるため、**「1件だけ」を条件にする安全策を必ず入れる**。

## 仕様

### 記録時（`-Record`）

`wait_after` の質問（v3追記）の**直後に**、続けて次を聞く。

```
対象者ごとに表示が変わる操作はどれですか？（全 12 手順）
  1: goto http://.../menu
  ...
  5: click tr.p-selectable-row (山田 太郎)
  ...
番号をカンマ区切りで入力（Enterで設定しない）: 5
```

- 一覧の表示形式・番号は `wait_after` の質問と同じ（`Get-ActionDesc` を使う）
- **複数可**（カンマ区切り）。Enterのみなら設定しない
- 不正な番号は警告を出して**その番号だけ無視**する（`wait_after` と同じ扱い）
- **`click` 以外が選ばれたら警告を出して無視する**（位置で押すのはクリックだけのため）
- 選ばれた手順は：
  - `"by_index": true` を付ける
  - **`text` を保存しない**（氏名が残ると照合で外れるため）
  - `"index": <記録時にそのセレクタで取れたものの中で何番目か（1始まり）>` を付ける

### 再生時

`by_index: true` の click は、既存のボタン名照合を**一切行わず**、次の手順で押す。

1. セレクタで取れる要素のうち、**画面に見えているもの**を数える
2. **ちょうど1件** → それを押す
3. **0件** → 失敗（`action_timeout_ms` まで待ってから）
4. **2件以上** → **失敗。押さない**

★4が本仕様の要。選択後の画面に宛名番号が出ないため、誤った対象を押しても気づく手段がない。
**迷ったら止まる**を構造として持たせる。

- `index` が 1 以外の場合も、上記の「見えているものがちょうど1件」を満たすときのみ押す。
  複数件から `index` 番目を選ぶ動作は**しない**（誤選択の余地を作らないため）
- 失敗時のメッセージは件数を含めること。例：
  - `位置で押す対象が2件見つかりました(1件のはず): tr.p-selectable-row`
  - `位置で押す対象が見つかりません: tr.p-selectable-row`
- 押す方法は既存の `go()`（`click()` があればそれ、無ければ作ったマウス操作）をそのまま使う

### 元に戻す方法

方式が合わなかった場合、記録ファイルの該当手順から `by_index` / `index` を消し、
`"text": "<氏名>"` を書き戻せば従来の動きに戻る。README に明記すること。

### README

第2部 手順2（記録）に、この質問と答え方を追記する。
第4部のアクション一覧に `by_index` / `index` を追記し、上の「元に戻す方法」も書く。
