# CAS Auto Report

業務システム（住民記録・印鑑登録）をブラウザ越しに自動操作し、対象者（宛名番号）ごとの帳票出力操作を繰り返すツール。

**1回だけ手で操作して覚えさせ、あとは対象者の人数分だけ自動で繰り返す。**
帳票の実体はサーバ側の出力管理に溜まる。回収は別ツールの担当で、本ツールの対象外。

[cas_cap](https://github.com/takakou32/cas_cap) の姉妹ツール。CDP（Chrome DevTools Protocol）でEdgeに繋ぐ仕組みは共通。

## 前提条件

- Windows 10/11 の PowerShell 5.1 以上（**追加インストール不要・外部依存ゼロ**）
- Microsoft Edge（Chromiumベース）
- 業務システムがEdgeのタブとして開くこと
- **手でできる操作であること**（記録は手の操作をそのまま覚えるだけなので、手でできない操作は自動でもできない）

# 第1部　最初に1回だけやること

## A. Edgeの起動方法を決める

このツールは、**デバッグポートが開いているEdge**にしか繋げない。
そのEdgeに業務システムが開いていなければならない。端末によって、その作り方が2通りある。

**まず、どちらの端末かを判定する。** 認証exeで業務システムを開いた状態で、PowerShellで次を実行する。

```powershell
Get-CimInstance Win32_Process -Filter "name='msedge.exe'" | ? { $_.CommandLine -notmatch '--type=' } | % CommandLine
```

出てきた行に `--remote-debugging-port=9222` が**含まれているかどうか**で分かれる。

### パターンA：認証exeがポート付きでEdgeを立てている（含まれていた）

**何もしなくてよい。** 業務システムを普段どおりexeで開けば、そのままツールが繋がる。
`start_edge.ps1` は使わない。

### パターンB：自分でEdgeを立てる（含まれていなかった／exeを使わない）

次のコマンドでEdgeを立てる。

```powershell
.\scripts\start_edge.ps1 -UserDataDir C:\edgework
```

`CDP接続確認OK` と出れば成功。空のEdgeウィンドウが開く。

> **`-UserDataDir` は Edge 136 以降では必須。**
> Edge 136 以降は、普段の保存場所のままだとデバッグポートの指定が**黙って無視される**（エラーは出ず、ポートだけ開かない）。
> 別の保存場所を指定したときだけ有効になる。公式の回避策は他にない。
> 保存場所が別になるので**普段のEdgeを閉じる必要はない**が、**ログイン状態やお気に入りは引き継がれない**。

パターンBのEdgeで業務システムを開くには、**そのEdgeで直接ログインする**必要がある。
認証exeを経由しないと入れないシステムでは、パターンBでは業務システムを扱えない
（練習ページでツールの動きを確かめることはできる）。
この場合の最後の手段は「付録：Edge全体の保存場所を移す」を参照。

## B. 設定ファイルを作る

1. `config\config.sample.json` をコピーして `config\config.json` を作る

2. Aで用意したEdgeで業務システムを開いた状態で、タブ一覧を表示する

   ```powershell
   .\powershell\cdp_print.ps1 -List
   ```
   ```
   接続成功。ページ数: 2
     [0] New Tab
         edge://newtab/
     [1] ○○システム
         https://app.example.local/xxx/menu
   ```

3. 業務システムのURLのうち、他のタブと区別できる一部分（上の例なら `app.example.local`）を、
   `config\config.json` の `target_url_keyword` に書く。他の項目は最初はそのままでよい

# 第2部　帳票1種類ごとの手順

**手順1〜6を上から順に。** 2種類目の帳票は、また手順1から繰り返す。

各手順に「コマンド」と「ランチャー」の2通りを書いてある。**どちらか好きなほうでよい**（やることは同じ）。
ランチャーは `gui\launcher.bat` をダブルクリックで開く。画面の説明は第3部にある。

## 手順1. 業務システムを基準画面にする

1. 第1部Aのやり方でEdgeを用意し、業務システムを開く
2. **帳票出力を始めるときにいつも最初に見る画面**（メニューのトップなど）まで進める

この画面を以後**「基準画面」**と呼ぶ。記録も再生も、毎回ここから始まる。

## 手順2. 操作を1回記録する

記録に使う宛名番号を1つ決めて（例 `1234567890`）、帳票名も決める（例 `R001_住民票`）。

**コマンド**
```powershell
.\powershell\cdp_print.ps1 -Record -Job R001_住民票 -Atena 1234567890
```

**ランチャー**
「3. 実行モード」で **( )記録** を選び、**記録: 帳票名** と **宛名番号** を入れて **[実行]**

---

`=== 操作記録を開始しました ===` と出たら記録中。ここから：

1. **ブラウザに切り替えて、普段どおりに1回、帳票出力を最後までやる**
   - 宛名番号は、上で指定した番号を**キーボードで手入力**する（貼り付けやオートコンプリートだと記録されないことがある）
   - 印字項目のチェックも普段どおりに入れる・外す
   - 出力ボタンを押し、確認ダイアログがあれば「はい」まで押して、出力が終わるところまで進める

2. **黒い窓（PowerShell）に戻って Enter**。記録が止まり、手順の一覧が出る

3. **どれが「出力実行」ボタンかを番号で選ぶ**
   ```
   どれが「出力実行」ボタンですか？（記録した最後の 4 クリック）
     1: 検索  [#btn-search]
     2: 1234567890 山田 太郎  [li.result-row]
     3: 発行  [#btn-issue]          ← これ
     4: はい  [#btn-confirm-yes]
   選んだクリック以降の手順は、-DryRun のとき実行しません。
   番号を入力してください（Enterのみなら 4 = 最後のクリック）: 3
   ```
   確認ダイアログの「はい」ではなく、**出力ボタンのほう**を選ぶ（試し実行で手前に止めるため）

4. **「実行後に待たせる操作」を番号で選ぶ**（無ければ Enter だけ）
   ```
   実行後に待たせる操作はどれですか？（全 13 手順）
     1: goto http://…/menu
     2: click #link-shomei (証明書発行)
     3: expect_url http://…/app.html
     4: fill #input-atena = 1234567890
     5: click #btn-search (検索)
     6: click li.result-row (1234567890 山田 太郎)      ← この後にプレビューが作られる
     7: setcheck 世帯主 = False
     …
    11: click #icon-preview (プレビュー)
    12: click #btn-issue (発行)
    13: click #btn-confirm-yes (はい)
   番号をカンマ区切りで入力（Enterで設定しない）: 6
   ```
   **どこで待つかを人が指名する仕掛け**。次の場合に使う：
   - その操作の後、画面が裏で印刷プレビューを作り始め、**くるくるが出ている間はボタンを押しても効かない**
   - 押しても効かないが、画面の中身は変わらないので、ツールの「画面が落ち着くまで待つ」がすり抜ける

   選び方：
   - **効かなかったボタンではなく、その手前の操作（＝くるくるが始まるきっかけの操作）を選ぶ**
   - **★最後の手順（出力実行や、その後の「はい」）も選んでおくとよい。**
     1人目の印刷プレビューが出来上がる前に2人目を始めると、業務システム側の処理が壊れて
     `Cannot read properties of null` のようなエラーが出ることがある（下の「困ったとき」参照）
   - 複数あるときはカンマ区切り（`6,11`）。空白が混じってもよい
   - 何も無ければ Enter だけ
   - 数字でない・範囲外の番号は警告が出て**その番号だけ無視**され、正しい番号は採用される

   待つ長さは `config/config.json` の **`wait_after_ms`（既定 5000ms）**。
   記録ファイルには秒数が入らないので、**録り直さずに設定だけで調整できる**。

5. **「対象者ごとに表示が変わる操作」を番号で選ぶ**（無ければ Enter だけ）
   ```
   対象者ごとに表示が変わる操作はどれですか？（全 12 手順）
     1: goto http://…/menu
     2: click #link-shomei (証明書発行)
     3: expect_url http://…/app.html
     4: fill #input-atena = {{atena}}
     5: click #btn-search (検索)
     6: click tr.p-selectable-row (山田 太郎)      ← 一覧の行。人が変われば表示も変わる
     7: setcheck 世帯主 = False
     …
    11: click #btn-issue (発行)
    12: click #btn-confirm-yes (はい)
   番号をカンマ区切りで入力（Enterで設定しない）: 6
   ```
   **一覧の行に宛名番号が出ず、氏名だけが表示される画面のための指定**。
   そのままだと記録した氏名（例「山田 太郎」）がボタン名として残り、
   2人目からは「佐藤 花子」なので照合が外れ、`クリック対象が見つかりません` で失敗する。

   ここで選んだクリックは、**ボタン名を見ずに、画面に出ている要素をそのまま押す**ようになる。
   押すのは**見えているものがちょうど1件のときだけ**で、**2件以上なら押さずに失敗する**
   （誤った対象者の帳票を出さないため。宛名番号で検索した結果は1件になる、という前提を使っている）。

   選び方：
   - **一覧から対象者を選ぶクリック**を選ぶ
   - 複数あるときはカンマ区切り（`6,9`）。空白が混じってもよい
   - 何も無ければ Enter だけ
   - 数字でない・範囲外の番号は警告が出て**その番号だけ無視**される
   - **クリック以外の手順（goto / fill / setcheck / expect_url）を選ぶと警告が出て無視される**（位置で押せるのはクリックだけ）

6. **次の表示を確認する**
   ```
   宛名番号を {{atena}} に置換: 2 箇所                 ← 1以上であること
   出力実行ボタン: 発行 [#btn-issue] （final=true）     ← 3で選んだボタンであること
     操作後に待つ: 手順 6 click li.result-row (1234567890 山田 太郎) （wait_after=true）
     位置で押す: 手順 6 click tr.p-selectable-row (位置で押す) （by_index=true / index=1）
       ボタン名「山田 太郎」は保存しません（対象者ごとに変わるため）
   保存先: jobs\R001_住民票.json
   ```
   置換の行の代わりに「宛名番号 '…' が手順のどこにも見つかりませんでした」と出たら、その記録は使えない。
   宛名番号の入力方法を見直して録り直す

## 手順3. 対象者リストを置く

**`targets` フォルダは自分で作る**（`jobs` と `output` はツールが自動で作るが、`targets` は置く側なので作られない）。

```powershell
mkdir targets
```

その中に `targets\R001_住民票.csv`（`targets\<帳票名>.csv`）を作る。1列目が宛名番号、1行目は見出し。
2列目以降は無視されるのでメモを書いてよい。

```csv
atena,氏名
1234567890,山田 太郎
1234567891,佐藤 花子
1234567892,鈴木 一郎
```

## 手順4. 1件だけ試す（出力ボタンは押さない）

**業務システムの画面を基準画面に戻してから。**

**コマンド**
```powershell
.\powershell\cdp_print.ps1 -Job R001_住民票 -DryRun -Limit 1
```

**ランチャー**
**(●)実行（帳票出力）** を選び、**[再読込]** を押して **実行: 帳票** から帳票を選ぶ。
**[×] DryRun** にチェック、**件数上限** に `1`。**[実行]**

---

ブラウザが自動で動き、**出力ボタンの手前で止まる**。
画面を目で見て、対象者と印字項目のチェックが正しいことを確認する。

うまくいかないときは「トラブルシューティング」へ。手順2から録り直すのが早いことが多い。

## 手順5. 本番を流す

**業務システムの画面を基準画面に戻してから。**

**コマンド**
```powershell
.\powershell\cdp_print.ps1 -Job R001_住民票
```

**ランチャー**
**[ ] DryRun** のチェックを外し、**件数上限** を `0` に戻して **[実行]**

---

対象者リストの人数分だけ自動で繰り返す。1件ごとに `ledger.csv` に結果が追記される。

## 手順6. 結果を確認する・やり直す

`ledger.csv` を開いて、`fail` の行がないか確認する。`fail` の行には理由が書いてある。

**やり直しは、手順5と同じ操作をもう一度するだけ。**
`ok` の件は飛ばし、`fail` の件と未処理の件だけを処理する。
途中で中断した場合も同じで、続きから再開される。

**コマンド**


**ランチャー**
**実行: 帳票** で **(全部)** を選んで **[実行]**

`gui\launcher.bat` をダブルクリックで開く。窓は4段。

```
1. Edge起動        ポート [9222]                        [Edge起動]
2. 共通設定        Config [config/config.json] [参照...]
                   CDP URL(任意) [            ]

                   件数上限(0=無制限) [0]
4. 実行                                                  [実行]
```

**ボタンを押すと別の黒い窓（PowerShell）が開いて、そこで処理が動く。**
表示を読んだり、Enterや番号を打ったりするのはその黒い窓のほう。ランチャーの窓は開いたままでよい。
正常に終わると黒い窓は自動で閉じる。エラーのときは閉じずに残るので、内容を読んでからEnterで閉じる。

| 欄 | 意味 |
|---|---|
| ポート／[Edge起動] | `start_edge.ps1` を呼ぶ。**保存場所を指定できないので Edge 136 以降では使えない**（第1部Aのコマンドで立てる） |
| Config | 設定ファイル。通常 `config/config.json` のまま |
| CDP URL(任意) | 空でよい。ポートを変えたときだけ `http://localhost:ポート` を入れる |
| 記録: 帳票名／宛名番号 | 記録モードのときだけ使う。コマンドの `-Job` `-Atena` |
| 実行: 帳票 | 実行モードのときだけ使う。`(全部)` か帳票名。**記録した直後は [再読込] を押さないと一覧に出ない** |
| DryRun | コマンドの `-DryRun` |
| 証跡スクショを撮る | コマンドの `-Evidence both` |
| 件数上限 | コマンドの `-Limit`。0 なら無制限 |

# 第4部　仕様

## 記録の決まり

- **必ず基準画面から録り始める。** 再生は1件ごとに手順の先頭から流す。先頭が基準画面への遷移になっていないと、前の件の画面が残ったまま次の件を処理してしまう
- **SPA（リロードなしで画面が変わるシステム）では、基準画面もアプリの中の画面にする。** SPAと判定された手順は再生時にリロードせず遷移するため、アプリの外のページから録ると再生時に開けない
- 宛名番号は `-Atena` に指定した値を**そのまま手入力**する。保存時にその値を探して `{{atena}}` に置き換える
- クリックが1つも記録されなかった場合は**保存しない**（押す操作が抜けた手順は帳票が出ないため）
- クリックで画面が変わった場合、そのクリックの直後に `expect_url`（そのURLになったことの確認）が記録される。**クリック自体は必ず残る**
- チェックボックス／ラジオは `setcheck` として記録される。「押した」ではなく「**最終的にどの状態であるべきか**」を保存するので、対象者ごとに初期状態が違っても指定どおりに揃う

## コマンドのオプション

| オプション | 説明 |
|------|------|
| `-Job <帳票名>` | 処理する帳票。省略すると `jobs/` の全帳票を名前順に処理 |
| `-DryRun` | 出力実行ボタン（`final`）と**それ以降の手順**を行わない。手前までは全部流す。台帳には `dry` と記録される |
| `-Limit N` | 全体でN件処理したら終了する |
| `-Evidence <値>` | 証跡スクリーンショット（`none`/`before`/`after`/`both`）。設定ファイルの値を上書きする |
| `-Config <パス>` | 設定ファイルを指定する（既定 `config/config.json`） |
| `-CdpUrl <URL>` | CDPのURLを上書きする |
| `-List` | タブ一覧を表示して終了 |
| `-Record -Job <帳票名> -Atena <宛名番号>` | 記録モード |

証跡スクリーンショットは `output/<帳票名>/<宛名番号>_before.png`（出力実行ボタンの直前）と
`_after.png`（手順を最後まで流し終えた後）に保存される。`-DryRun` では `_before.png` だけになる。

## 実行結果（ledger.csv）

リポジトリ直下の `ledger.csv` に1件ずつ追記される（UTF-8 BOM付き。Excelでそのまま開ける）。

```csv
job,atena,timestamp,status,error
R001_住民票,1234567890,2026-08-27 19:00:00,ok,
R001_住民票,1234567891,2026-08-27 19:00:12,fail,クリック対象が見つかりません: ...
R001_住民票,1234567892,2026-08-27 19:00:20,dry,
```

- status は `ok`（本番で成功）／`fail`（失敗）／`dry`（`-DryRun` で流した）の3種類
- 同じ 帳票×宛名番号 の**最新行が `ok` なら次の実行では飛ばす**
- `fail` と `dry` は次の実行で処理される。**`-DryRun` で試したあと、そのまま本番を流してよい**（台帳を消す必要はない）

## 失敗したときの動き

- 対象が見つからない・待機タイムアウト・例外が起きたら、**その件はそこで打ち切って次の宛名番号へ進む**。
  ズレた画面のまま進んで、誤った対象で出力ボタンを押す事故を防ぐため
- 実行全体は止まらない。ただし連続失敗が `max_consecutive_fail`（既定5）に達したら、その帳票は中断して次の帳票へ
- 各件は必ず手順の先頭（基準画面への遷移）から始まるので、前の件がどこで転んでも立て直せる

## 設定ファイルの項目（config/config.json）

| キー | 説明 |
|------|------|
| `cdp_url` | CDP接続先 |
| `target_url_keyword` | 対象タブのURLに含まれるキーワード |
| `settle_ms` | 待機後の追加待ち時間(ms) |
| `stable_ms` | DOMがこの時間変化しなくなったら描画完了とみなす(ms) |
| `load_timeout_ms` | 描画完了を待つ最大時間(ms) |
| `action_timeout_ms` | クリック/入力の対象要素を待つ最大時間(ms)。超えたらその件は失敗 |
| `wait_after_ms` | 記録時に「実行後に待たせる」と指定した手順の後で待つ時間(ms)。既定 5000 |
| `ready_selector` | 指定するとこの要素が表示されるまで待つ（最も確実） |
| `spa_mode` | SPAのとき true。記録時に自動判定した値が手順ファイル側に入る |
| `interval_ms` | 1人ぶん終わってから次の人に移るまでの待ち時間(ms)。前の人の処理が終わり切らないうちに次を始めて失敗する場合は、ここを上げる |
| `max_consecutive_fail` | 連続失敗がこの数に達したらその帳票を中断する |
| `evidence` | 証跡スクリーンショット: `none` / `before` / `after` / `both` |
| `viewport` | 描画サイズ（幅・高さ・拡大率） |

## アクション一覧（jobs/*.json）

| type | 説明 | パラメータ |
|------|------|-----------|
| `goto` | URLに遷移（`spa_mode`ならリロードせず pushState で遷移） | `url` |
| `expect_url` | 直前のクリックで狙った画面へ移ったことを確認する（移動はしない）。ならなければその件は失敗 | `url` |
| `fill` | テキスト入力 | `selector`, `value` |
| `click` | 要素をクリック。セレクタで当てた要素をボタン名でも検証する | `selector`, `text`, `final`, `by_index`, `index` |
| `setcheck` | チェックボックス/ラジオを指定の状態にする（違うときだけクリック） | `selector`, `label`, `checked` |
| `select` | セレクトボックス選択 | `selector`, `value` |
| `wait` | 要素の表示を待機 | `selector`, `timeout` |
| `keyboard` | キー入力 | `key` |

どの type にも `"wait_after": true` を付けられる。付いた手順は、その手順を実行した**後**に
`wait_after_ms`（既定 5000ms）だけ止まる。画面が裏で印刷プレビューを作っている間はボタンを押しても効かないが、
くるくるは絵が回っているだけでDOMが変わらないため、通常の待機ではすり抜けてしまう。その対策。
画面の状態は見ずに決めた時間だけ待つ。`-DryRun` でも同じように待つ（出力実行ボタン以降は実行しないので、そこに付けた指定は効かない）。
この指定は記録の最後に人が番号で指名する（第2部 手順2）。待つ時間は記録ファイルではなく設定側にあるので、録り直さずに変えられる。

`click` に `"by_index": true` が付いていると、**ボタン名(`text`)での照合を一切せず、位置で押す**。
一覧の行に宛名番号が出ず氏名だけの画面で、2人目から照合が外れるのを避けるための指定（第2部 手順2 の5番で選ぶ）。
動きは次のとおり：

1. セレクタで取れる要素のうち、**画面に見えているもの**を数える
2. **ちょうど1件** → それを押す
3. **0件** → `action_timeout_ms` まで待って、それでも出なければその件は失敗
4. **2件以上** → **押さずに失敗**（`位置で押す対象が2件見つかりました(1件のはず): …`）

4が要。選択後の画面に宛名番号が出ない画面では、誤った対象を押しても気づく手段が無いため、迷ったら止まる作りにしてある。
`index` は記録時にその要素が何番目だったかの控えで、**再生では対象を選ぶのに使わない**
（複数件から `index` 番目を選ぶ動作はしない。`index` が 1 以外でも「見えているものがちょうど1件」のときだけ押す）。
`by_index` の付いたクリックは `text` を持たない（氏名が残ると照合で外れるため、記録時に保存していない）。

**元に戻す方法**：方式が合わなかったときは、記録ファイル（`jobs/<帳票名>.json`）の該当手順から
`"by_index"` と `"index"` の行を消し、代わりに `"text": "<記録時の氏名>"` を書き足せば、従来の
「ボタン名で照合するクリック」に戻る。録り直す必要はない。

```json
  { "type": "click", "selector": "tr.p-selectable-row", "by_index": true, "index": 1 }
  ↓ 元に戻す
  { "type": "click", "selector": "tr.p-selectable-row", "text": "山田 太郎" }
```

`{{atena}}` は再生時に対象者の宛名番号に差し替わる（`value` / `text` / `selector` / `url` のどれでも）。
`expect_url` の照合は、クエリ文字列を無視して「オリジン＋パス＋ハッシュ」で比べる。
`text` に `{{atena}}` を含むクリックは、差し込み後の**宛名番号だけ**で部分一致させる。

# 第5部　困ったとき

## `CDP接続確認OK` にならない／接続エラーになる

まず `edge://version` でEdgeのバージョンを確認する。

- **136 以降** → `-UserDataDir` を付けずに立てた可能性が高い。この場合デバッグポートの指定は**黙って無視される**。
  `.\scripts\start_edge.ps1 -UserDataDir C:\edgework` で立て直す
- **135 以前** → Edgeが裏で生き残っている可能性。`Get-Process msedge` で何か出たら
  `Stop-Process -Name msedge -Force` で全部落としてから立て直す

ポートが開いているかの確認は `irm http://localhost:9222/json/version`。

## 認証exeが必要なのに、exeのEdgeにポートが無い

Edge 136 以降でこの状態になると、「認証があるEdge」と「デバッグできるEdge」が別物になり、そのままでは繋げない。
検証端末であれば「付録：Edge全体の保存場所を移す」で通る可能性がある。
**本番接続端末では行わず、ベンダー・端末管理側へ相談すること**（exeがポートを使う設計なら、ベンダー側も同じ問題に当たっているはず）。

## 対象タブが見つからない

`-List` でタブ一覧を確認し、`target_url_keyword` を修正する。

## 全部 fail になる

- 画面の作りが記録時から変わっている可能性が高い。録り直す
- `action_timeout_ms` を増やす（描画が遅いだけのことがある）
- `ready_selector` に画面共通の目印要素を指定すると安定する

## 「画面遷移が記録と違います」で失敗する

- 記録したときと画面の出方が変わっている。`load_timeout_ms` を増やすか、録り直す
- 照合はクエリ文字列を無視した「オリジン＋パス＋ハッシュ」で行う。
  **パスそのものが実行のたびに変わる作り**（内部IDが乗る等）なら録り直しでは直らないので、
  手順ファイルから該当の `expect_url` の行を手で消す

## 2人目以降で失敗する

### 業務システム側のJavaScriptエラーが出る（`Cannot read properties of null` など）

**1人目は最後まで成功しているのに、2人目に入る所で落ちる**場合、
**1人目の印刷プレビューが出来上がる前に、2人目を始めてしまっている**ことが多い。

このエラーはツールが出したものではなく、**業務システム側の処理が落ちている**。
前の人の画面の後片付けが終わらないうちに次の操作をすると、システムが「あるはずの部品が無い」状態になる。

対処は2つ。手軽なほうから：

1. **`config/config.json` の `interval_ms` を上げる**（例 1000 → 5000）。
   1人ぶん終わってから次に移るまでの待ち時間。**録り直しも編集も要らない**
2. **記録ファイルの最後の手順に `"wait_after": true` を足す**（録り直し不要。手で1行足すだけ）

   ```json
   {
       "type": "click",
       "selector": "#btn-issue",
       "text": "発行",
       "final": true,
       "wait_after": true
   }
   ```

   待つ長さは `wait_after_ms`（既定5000ms）。プレビューがそれより長くかかるなら上げる。

**証跡スクリーンショットを撮っている場合は2のほうがよい。**
`interval_ms` は台帳に書いた後の待ちなので、スクリーンショットがプレビュー完成前に撮られてしまう。

### 対象者を選ぶところで失敗する（`クリック対象が見つかりません`）

一覧の行に宛名番号が表示されず氏名だけの場合、記録した氏名が2人目以降で合わずに失敗する。
記録し直して**「対象者ごとに表示が変わる操作」でその手順を指名する**（第2部 手順2の5番）。

## 宛名番号が差し替わらない

- 記録の最後に「宛名番号 '…' が手順のどこにも見つかりませんでした」と出ていないか確認する
- 宛名番号は入力欄に**キーボードで手入力**してから録る（貼り付け・オートコンプリートだと記録されないことがある）

# 付録　Edge全体の保存場所を移す

**本番接続端末では行わないこと。** 端末のEdgeの設定を書き換えるため、チームの変更手順に沿うべき作業になる。

認証exeがポートを付けずにEdgeを立てる端末で、Edge 136 以降の場合の最後の手段。
Edge全体の保存場所を普段と別の場所に移すと、exeが立てるEdgeにもデバッグポートが効くようになる。

> この方法が効くかどうかは公式に記載がない。効かなければ戻して、別の手段を検討すること。

**入れる**
```powershell
reg add HKCU\Software\Policies\Microsoft\Edge /v UserDataDir /t REG_SZ /d C:\edgework
taskkill /f /im msedge.exe
```
1行目で保存場所を変える設定を入れ、2行目でEdgeを全部落とす（起動し直すまで効かないため）。

**確認する**

認証exeで業務システムを開いてから、
```powershell
irm http://localhost:9222/json
```
タブ一覧が返り、業務システムのURLがあれば成功。第1部Bへ進む。

**戻す（作業が終わったら必ず）**
```powershell
reg delete HKCU\Software\Policies\Microsoft\Edge /v UserDataDir /f
taskkill /f /im msedge.exe
```

**入れている間に起きること**

- その端末のEdgeが**全部**新しい保存場所（`C:\edgework`）を使う。お気に入り・履歴・ログイン状態が空の状態で表示される
- **消えるわけではない。** 普段の保存場所にそのまま残っており、設定を戻せば元どおりになる
- 普段のブラウザとして使うと不便なので、**作業の間だけ入れて、終わったら戻す**運用にする
- `C:\edgework` フォルダは設定を戻した後、不要なら削除してよい
