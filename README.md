# CAS Auto Report

業務システム（住民記録・印鑑登録）をブラウザ越しに自動操作し、対象者（宛名番号）ごとの帳票出力操作を繰り返すツール。

帳票の実体はサーバ側の出力管理に溜まる。**回収は別ツールの担当で、本ツールの対象外。**

[cas_cap](https://github.com/takakou32/cas_cap) の姉妹ツール。CDP（Chrome DevTools Protocol）でEdgeにアタッチする仕組み・設定ファイルの形は cas_cap と共通。

## 仕組み

```
[Edge + デバッグポート] ← CDP接続 ← [CAS Auto Report (本ツール)]
        ↑
   [認証exe] がタブを追加
```

1. Edgeをデバッグポート付きで起動
2. 認証exeがそのEdgeインスタンスにタブを追加
3. 本ツールがCDP経由でEdgeに接続し、対象タブを操作する

帳票1種類につき1回だけ操作を記録し（`-Record`）、あとは対象者リストの人数分だけ再生する。

## 前提条件

- Windows 10/11 の PowerShell 5.1 以上（**追加インストール不要・外部依存ゼロ**）
- Microsoft Edge（Chromiumベース）
- 認証exeがシステムのEdgeを利用する構成であること

---

## 設定ファイルの項目（config/config.json）

作り方は「使い方」の手順3を参照。最初に書き換えるのは `target_url_keyword` だけでよい。

| キー | 説明 |
|------|------|
| `cdp_url` | CDP接続先 |
| `target_url_keyword` | 対象タブのURLに含まれるキーワード |
| `settle_ms` | 待機後の追加待ち時間(ms) |
| `stable_ms` | DOMがこの時間変化しなくなったら描画完了とみなす(ms) |
| `load_timeout_ms` | 描画完了を待つ最大時間(ms) |
| `action_timeout_ms` | クリック/入力の対象要素を待つ最大時間(ms)。超えたらその件は失敗 |
| `ready_selector` | 指定するとこの要素が表示されるまで待つ（最も確実） |
| `spa_mode` | SPA（リロードなし遷移）のとき true。記録時に自動判定した値が手順ファイル側に入る |
| `interval_ms` | 1件処理するごとの待ち時間(ms) |
| `max_consecutive_fail` | 連続失敗がこの数に達したらその帳票を中断する |
| `evidence` | 証跡スクリーンショット: `none` / `before` / `after` / `both` |
| `viewport` | 描画サイズ（幅・高さ・拡大率） |

## 使い方（この通りに進める）

帳票1種類ごとに、**「1回手で操作して覚えさせる → 対象者リストを置く → 流す」** の順で進める。
以下は帳票1種類ぶんの手順。2種類目からは手順4〜7を繰り返す。
コマンドを打たずに画面から使う場合は、下の「GUIで使う（ランチャー）」を見る（手順の番号は対応している）。

### 手順1. Edgeをデバッグポート付きで起動する

1. 開いているEdgeを**全部閉じる**（閉じずに起動するとデバッグポートが効かない）
2. リポジトリのフォルダでPowerShellを開き、次を実行する
   ```powershell
   .\scripts\start_edge.ps1
   ```
3. `CDP接続確認OK` と表示されたら成功。Edgeが空のウィンドウで開いている

### 手順2. 業務システムを開く

1. 認証exeを通常どおり起動する。業務システムが手順1のEdgeの新しいタブとして開く
2. ログインして、**帳票出力を始めるときにいつも最初に見る画面**（メニューのトップなど）まで進める。ここを以後「基準画面」と呼ぶ

### 手順3. 設定ファイルを作る（初回だけ）

1. サンプルを複製する
   ```powershell
   copy config\config.sample.json config\config.json
   ```
2. タブ一覧を表示する
   ```powershell
   .\powershell\cdp_print.ps1 -List
   ```
   ```
   接続成功。ページ数: 2
     [0] New Tab
         edge://newtab/
     [1] ○○システム
         https://app.example.local/xxx/menu
   ```
3. 業務システムのタブのURLのうち、他のタブと区別できる一部分（上の例なら `app.example.local`）を `config\config.json` の `target_url_keyword` に書く。他の項目は最初はそのままでよい

### 手順4. 帳票の操作を1回記録する

1. 業務システムの画面を**基準画面**にしておく
2. これから記録に使う宛名番号を1つ決めて、次を実行する（帳票名は自分で決める。例では `R001_住民票`）
   ```powershell
   .\powershell\cdp_print.ps1 -Record -Job R001_住民票 -Atena 1234567890
   ```
   `=== 操作記録を開始しました ===` と出たら記録中
3. ブラウザに切り替えて、**普段どおりに1回、帳票出力を最後までやる**
   - 宛名番号の欄には、2で指定した番号（例では `1234567890`）を**キーボードで手入力**する（貼り付けやオートコンプリートだと記録されないことがある）
   - 印字項目のチェックも普段どおりに入れる・外す
   - 出力ボタンを押し、確認ダイアログがあれば「はい」まで押して、出力が完了するところまで進める
4. PowerShellのウィンドウに戻り、**Enter** を押す。記録が止まり、記録した手順が一覧で表示される
5. 「どのクリックが出力実行ボタンか」を聞かれる。最後の5回分のクリックが番号付きで出るので、**出力ボタンの番号**を入力してEnter
   ```
   どれが「出力実行」ボタンですか？（記録した最後の 4 クリック）
     1: 検索  [#btn-search]
     2: 1234567890 山田 太郎  [li.result-row]
     3: 発行  [#btn-issue]          ← これ
     4: はい  [#btn-confirm-yes]
   選んだクリック以降の手順は、-DryRun のとき実行しません。
   番号を入力してください（Enterのみなら 4 = 最後のクリック）: 3
   ```
   - 出力ボタンの後に確認ダイアログの「はい」がある場合は、**「はい」ではなく出力ボタンのほう**を選ぶ（試し実行のとき出力ボタンの手前で止めるため）
6. 次の表示を確認する（置換の行は5の質問の前、残り2行は後に出る）
   ```
   宛名番号を {{atena}} に置換: 2 箇所                 ← 1以上であること
   出力実行ボタン: 発行 [#btn-issue] （final=true）     ← 5で選んだボタンになっていること
   保存先: jobs\R001_住民票.json
   ```
   置換の行の代わりに「宛名番号 '…' が手順のどこにも見つかりませんでした」と出たら、その記録は使えない。3の宛名番号の入力方法を見直して録り直す

### 手順5. 対象者リストを置く

`targets\R001_住民票.csv`（`targets\<手順4の帳票名>.csv`）を作り、1列目に宛名番号を並べる。1行目は見出し。2列目以降は無視されるのでメモを書いてよい。

```csv
atena,氏名
1234567890,山田 太郎
1234567891,佐藤 花子
1234567892,鈴木 一郎
```

### 手順6. 1件だけ試す（出力ボタンは押さない）

1. 業務システムの画面を**基準画面**にしておく
2. 次を実行する
   ```powershell
   .\powershell\cdp_print.ps1 -Job R001_住民票 -DryRun -Limit 1
   ```
3. ブラウザが自動で動き、出力ボタンの**手前**で止まる。画面を目で見て、対象者・印字項目のチェックが正しいことを確認する
4. `ledger.csv` に `dry` の行が1つ増えている。このまま手順7へ進んでよい（台帳を消す必要はない）

うまくいかないときは「トラブルシューティング」を見る。手順4から録り直すのが早いことが多い。

### 手順7. 本番を流す

1. 業務システムの画面を**基準画面**にしておく
2. 次を実行する
   ```powershell
   .\powershell\cdp_print.ps1 -Job R001_住民票
   ```
3. 対象者リストの人数分だけ自動で繰り返す。1件ごとに `ledger.csv` に `ok` または `fail` が追記される
4. 終わったら `ledger.csv` を開き、`fail` の行がないか確認する。`fail` の行には理由が書いてある

### 手順8. 失敗した件をやり直す・途中から再開する

**同じコマンドをもう一度実行するだけ**。`ok` の件は飛ばし、`fail` の件と未処理の件だけを処理する。
途中でPowerShellを閉じてしまった場合も同じ。

### 2種類目以降の帳票

Edgeと業務システムが開いたままなら、手順4〜7を帳票ごとに繰り返す。

全帳票をまとめて流すときは `-Job` を付けずに実行する（`jobs\` にある手順を名前順に処理する）。

```powershell
.\powershell\cdp_print.ps1
```

`gui\launcher.bat` をダブルクリックする。「CAS Auto Report ランチャー」という窓が開く。窓は4段に分かれている。

```
1. Edge起動        ポート [9222]                        [Edge起動]
2. 共通設定        Config [config/config.json] [参照...]
                   CDP URL(任意) [            ]
3. 実行モード      (●)実行（帳票出力） ( )記録 ( )タブ一覧
                   記録: 帳票名 [        ]  宛名番号 [        ]
```

1. 開いているEdgeを**全部閉じる**
2. 「1. Edge起動」の **[Edge起動]** を押す（ポートは 9222 のまま）

6. 黒い窓に戻って **Enter**

コマンド版の手順5と同じ（`targets\<帳票名>.csv` を作る）。

1. 業務システムの画面を**基準画面**にしておく
2. 「3. 実行モード」で **(●)実行（帳票出力）** を選ぶ

5. **[実行]** を押す。ブラウザが自動で動き、出力ボタンの手前で止まる。画面を目で確認する

### 全帳票をまとめて流す

**実行: 帳票** で **(全部)** を選んで **[実行]**。`jobs\` にある手順を名前順に処理する。

### 各欄の意味

| 欄 | 意味 |
|---|---|
| ポート | Edgeのデバッグポート。通常 9222 のまま |
| Config | 設定ファイル。通常 `config/config.json` のまま |
| CDP URL(任意) | 空でよい。ポートを変えたときだけ `http://localhost:ポート` を入れる |
| 記録: 帳票名／宛名番号 | 記録モードのときだけ使う。コマンドの `-Job` `-Atena` |
| 実行: 帳票 | 実行モードのときだけ使う。`(全部)` か帳票名。**記録した直後は [再読込] を押さないと一覧に出ない** |
| DryRun | コマンドの `-DryRun` |
| 証跡スクショを撮る | コマンドの `-Evidence both`（出力ボタンの直前と、手順を流し終えた後の画面を保存） |
| 件数上限 | コマンドの `-Limit`。0 なら無制限 |

## 記録するときの決まり

- **必ず基準画面から録り始める。** 再生は1件ごとに手順の先頭から流す。先頭が基準画面への遷移になっていないと、前の件の画面が残ったまま次の件を処理してしまう
- **SPA（リロードなしで画面が変わるシステム）では、基準画面もアプリの中の画面にする。** SPAと判定された手順は再生時にリロードせず遷移するため、アプリの外のページから録ると再生時に開けない
- 宛名番号は `-Atena` に指定した値を**そのまま手入力**する。保存時にその値を探して `{{atena}}` に置き換える。見つからなければ警告が出る
- 出力ボタンは記録の最後に番号で選ぶ。選んだクリックに `"final": true` が付き、`-DryRun` のときはそのクリックと**それ以降の手順**を行わない
- クリックが1つも記録されなかった場合は保存しない（押す操作が抜けた手順は帳票が出ないため）
- クリックで画面が変わった（URLが変わった）場合、そのクリックの直後に `expect_url`（そのURLになったことの確認）が記録される。クリック自体は必ず残る
- チェックボックス／ラジオは `setcheck` として記録される。「押した」ではなく「最終的にどの状態であるべきか」を保存するので、対象者ごとに初期状態が違っても指定どおりに揃う

## コマンドのオプション

| オプション | 説明 |
|------|------|
| `-Job <帳票名>` | 処理する帳票。省略すると `jobs/` の全帳票を名前順に処理 |
| `-DryRun` | 出力実行ボタン（`final`）と**それ以降の手順**を行わない。手前までは全部流す。台帳には `dry` と記録される |
| `-Limit N` | 全体でN件処理したら終了する |
| `-Evidence <値>` | 証跡スクリーンショットの設定を上書きする（`none`/`before`/`after`/`both`） |
| `-Config <パス>` | 設定ファイルを指定する（既定 `config/config.json`） |
| `-CdpUrl <URL>` | CDPのURLを上書きする |
| `-List` | タブ一覧を表示して終了 |
| `-Record -Job <帳票名> -Atena <宛名番号>` | 記録モード |

証跡スクリーンショットは `output/<帳票名>/<宛名番号>_before.png`（出力実行ボタンの直前）と `_after.png`（手順を最後まで流し終えた後）に保存される。
`-DryRun` では出力実行ボタンの手前で止まるので `_before.png` だけになる。

## 実行結果（ledger.csv）

リポジトリ直下の `ledger.csv` に1件ずつ追記される（UTF-8 BOM付き。Excelでそのまま開ける）。

```csv
job,atena,timestamp,status,error
R001_住民票,1234567890,2026-08-27 19:00:00,ok,
R001_住民票,1234567891,2026-08-27 19:00:12,fail,クリック対象が見つかりません: ...
R001_住民票,1234567892,2026-08-27 19:00:20,dry,
```

- status は `ok`（本番で成功）／`fail`（失敗）／`dry`（`-DryRun` で流した）の3種類
- 同じ 帳票×宛名番号 の**最新行が `ok` なら次の実行では飛ばす**。中断しても続きから再開できる
- `fail` と `dry` は次の実行で処理される。**`-DryRun` で試したあと、そのまま本番を流してよい**（台帳を消す必要はない）

## 失敗したときの動き

- 対象が見つからない・待機タイムアウト・例外が起きたら、**その件はそこで打ち切って次の宛名番号へ進む**。
  ズレた画面のまま進んで、誤った対象で出力ボタンを押す事故を防ぐため（cas_capの「見つからなければスキップして続行」とは違う）
- 失敗しても実行全体は止まらない。ただし連続失敗が `max_consecutive_fail`（既定5）に達したら、その帳票は中断して次の帳票へ進む
- 各件は必ず手順の先頭（基準画面への遷移）から始まるので、前の件がどこで転んでも立て直せる

## アクション一覧（jobs/*.json）

| type | 説明 | パラメータ |
|------|------|-----------|
| `goto` | URLに遷移（`spa_mode`ならリロードせず pushState で遷移） | `url` |
| `expect_url` | 直前のクリックで狙った画面へ移ったことを確認する（移動はしない）。ならなければその件は失敗 | `url` |
| `fill` | テキスト入力 | `selector`, `value` |
| `click` | 要素をクリック。セレクタで当てた要素をボタン名でも検証する | `selector`, `text`, `final` |
| `setcheck` | チェックボックス/ラジオを指定の状態にする（違うときだけクリック） | `selector`, `label`, `checked` |
| `select` | セレクトボックス選択 | `selector`, `value` |
| `wait` | 要素の表示を待機 | `selector`, `timeout` |
| `keyboard` | キー入力 | `key` |

`{{atena}}` は再生時に対象者の宛名番号に差し替わる（`value` / `text` / `selector` / `url` のどれでも）。
`expect_url` の照合は、クエリ文字列を無視して「オリジン＋パス＋ハッシュ」で比べる（待つ上限は `load_timeout_ms`）。
`text` に `{{atena}}` を含むクリックは、差し込み後の**宛名番号だけ**で部分一致させる（氏名の書き方の揺れを照合に使わない）。

## トラブルシューティング

### CDPに接続できない

```
接続エラー: http://localhost:9222
```

- Edgeが起動しているか確認: `Get-Process msedge`
- デバッグポートが有効か確認: `Invoke-RestMethod http://localhost:9222/json`
- **全Edgeを閉じてから**デバッグポート付きで起動し直す（既存インスタンスがある状態で起動するとデバッグポートが無視される）

### 対象タブが見つからない

- `-List` でタブ一覧を確認し、`target_url_keyword` を修正する

### 全部 fail になる

- 画面の作りが記録時から変わっている可能性が高い。録り直す
- `action_timeout_ms` を増やす（描画が遅いだけのことがある）
- `ready_selector` に画面共通の目印要素を指定すると安定する

### 「画面遷移が記録と違います」で失敗する

- 記録したときと画面の出方が変わっている（URLが変わった／遷移に時間がかかる）。`load_timeout_ms` を増やすか、録り直す
- 照合はクエリ文字列を無視した「オリジン＋パス＋ハッシュ」で行う。パスそのものが実行のたびに変わる作りなら録り直しでは直らないので相談すること

### 宛名番号が差し替わらない

- 記録の最後に「宛名番号 '…' が手順のどこにも見つかりませんでした」と警告が出ていないか確認する
- 宛名番号を入力欄に**手で入力**してから録る（コピー貼り付け・オートコンプリートで `change` が飛ばないと記録されないことがある）
